# ResearchOS Backend

FastAPI backend for ResearchOS, implemented against the project's SRS, SDD,
Database Design Document, and API Design Document.

## Scope of this build pass

This is a **deep, fully-working build of three modules**, not a stub of all
twelve. Everything below is real, tested, working code:

| Module | Status |
|---|---|
| 1 — User Management | ✅ Fully implemented (register, login, JWT + refresh rotation, lockout after 5 failed attempts, profile, admin role/status changes) |
| 2 — Research Workspace | ✅ Fully implemented (create/list/get/update/archive, auto-owner-membership, activity log) |
| 3 — Literature Discovery | ✅ Fully implemented (concurrent search across 5 external sources with de-duplication, manual add, PDF upload, list/get) |
| 4–12 (AI Analysis, Knowledge Graph, Mentorship, Teams, Collaboration, Feed, Publication) | ⏸ Deferred — not built in this pass |

**Data stores**: PostgreSQL and Redis only, per scope. MongoDB, Qdrant, and
Neo4j (needed for Modules 4–6's AI features) are intentionally not wired up
yet — see [Database Design Document] for their planned schemas when that
work resumes.

## Important limitation: external literature APIs were not live-tested

Module 3's search fetchers (`app/services/literature_sources.py`) call
OpenAlex, arXiv, Semantic Scholar, Crossref, and PubMed. The sandbox this
backend was built in has an egress allowlist that does **not** include
those hosts, so live calls could not be exercised end-to-end during
development. What *was* verified:

- The fetchers correctly return an empty list per source on failure, and
  the endpoint correctly returns `502 UPSTREAM_SOURCE_ERROR` only when
  *every* source fails (confirmed by an actual test run against the
  blocked hosts — see `test_literature_search_all_sources_unreachable_returns_502`).
- The parsing logic follows each API's publicly documented response shape.

**Before relying on this in a real environment**, run one real search
request against each source and sanity-check the parsed fields — response
shapes for public APIs do drift over time.

## Requirements

- Python 3.12
- PostgreSQL 16
- Redis 7
- Docker + Docker Compose (recommended, for the easiest setup)

## Quick start (Docker Compose)

```bash
cp .env.example .env   # edit JWT_SECRET_KEY at minimum
docker compose up --build
```

This starts Postgres, Redis, and the API (running `alembic upgrade head`
automatically on boot). The API is then available at
`http://localhost:8000`, with interactive docs at `http://localhost:8000/docs`.

## Quick start (running directly on the host)

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# Start Postgres and Redis yourself (or point DATABASE_URL/REDIS_URL at
# existing instances), then:
cp .env.example .env
alembic upgrade head
uvicorn app.main:app --reload
```

## Running the tests

Tests run against a **real PostgreSQL database** (not SQLite), because the
schema uses Postgres-specific `ARRAY` and `JSONB` column types. Create a
separate test database once:

```sql
CREATE DATABASE researchos_test OWNER researchos;
```

Then:

```bash
pytest -q
```

23 tests cover: registration/duplicate detection/validation, login and
account lockout (FR-UM-10), JWT + refresh token rotation and revocation,
workspace CRUD and ownership/membership authorization boundaries (403s),
activity logging, paper add/list/get, PDF upload (including content-type
rejection), and the literature search failure-mode contract.

## Design decisions worth knowing about

- **UUID primary keys everywhere**, matching the Database Design Document.
- **Refresh tokens are rotated on every use** and stored server-side only
  as a SHA-256 hash (never the raw token), so a single refresh token can't
  be replayed after it's been used once.
- **Standard error envelope** (`{"error": {"code", "message", "details",
  "request_id"}}`) is enforced globally via FastAPI exception handlers, so
  every endpoint — including framework-level 404s and validation errors —
  returns the same shape described in the API Design Document.
- **Rate limiting** is a simple Redis `INCR` fixed-window counter (not a
  leaky bucket). It's intentionally simple; be aware it can allow a short
  burst right at a window boundary.
- **File storage** is local disk (`./storage`) behind a small
  `LocalDiskStorage` class in `app/services/storage_service.py`. Swapping
  to MinIO/S3 later (per the SDD) means implementing the same
  `save_paper_pdf` interface — no caller code should need to change.
- **The polymorphic `comments` table design from the Database Design
  Document was not implemented** in this pass since the Collaboration
  module is deferred; only the tables needed for Modules 1–3 were migrated.

## What's deliberately not here yet

- Modules 4–12 (AI paper analysis, knowledge graph, research-gap
  suggestions, notes, mentorship, teams, tasks/comments, feed, publication
  drafts) — no routes, models, or services for these.
- MongoDB, Qdrant, Neo4j connections.
- Celery / background job workers (paper analysis would need this).
- Email delivery for verification and password-reset links — those
  endpoints exist and return the correct contract shape, but no email is
  actually sent yet (see the comment in `app/routers/auth.py`).
- OAuth (Google) login — the `oauth_provider`/`oauth_id` columns exist on
  the `users` table for forward compatibility, but the callback flow isn't
  implemented.
